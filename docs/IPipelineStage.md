# IPipelineStage

The `IPipelineStage` interface defines the contract for individual processing units within the `coub-downloader` execution pipeline. It serves as the foundational abstraction that allows distinct operations—such as downloading, validation, conversion, and cleanup—to be chained together while maintaining a consistent flow of data and error handling. Implementations of this interface encapsulate specific logic for transforming input states into output results, enabling the `ConversionPipeline` to orchestrate complex media retrieval and processing tasks through a modular, composable architecture.

## API

### Properties

#### `string TaskId`
Gets the unique identifier associated with the current pipeline execution context. This ID is used to correlate logs, temporary files, and status updates across different stages of the same operation.

#### `bool Success`
Indicates whether the stage completed its operation without encountering a critical failure. A value of `false` typically implies that the `Error` property contains a descriptive message and that subsequent stages in the pipeline may be skipped depending on the pipeline's error handling strategy.

#### `string? OutputPath`
Contains the file system path to the result generated by this stage. If the stage does not produce a file artifact or if the operation failed, this property returns `null`.

#### `string? Error`
Holds the error message describing the reason for failure if `Success` is `false`. If the stage completed successfully, this property is `null`.

### Methods

#### `Task<DownloadTask> ExecuteAsync()` (DownloadStage)
Executes the download logic for a specific Coub URL.
*   **Return Value**: A `Task<DownloadTask>` representing the asynchronous operation. The result contains metadata about the downloaded file, including temporary storage paths and stream information.
*   **Exceptions**: Throws network-related exceptions if the source is unreachable, or `IOException` if writing to the disk fails.

#### `Task<ConversionResult> ExecuteAsync()` (ConversionStage)
Executes the media conversion logic, typically invoking an underlying FFmpeg process to merge audio and video streams or transcode formats.
*   **Return Value**: A `Task<ConversionResult>` containing the final output path and conversion statistics.
*   **Exceptions**: Throws if the converter binary is missing, if the input files are corrupted, or if the conversion process exits with a non-zero code.

#### `Task<object> ExecuteAsync()` (StageAdapter / Generic)
Executes the generic stage logic. This overload is used by the `StageAdapter` to normalize execution across different stage types when the specific return type is handled via polymorphism or casting within the pipeline engine.
*   **Return Value**: A `Task<object>` wrapping the specific result of the stage execution.
*   **Exceptions**: Propagates any exception thrown by the underlying concrete stage implementation.

### Pipeline Configuration Members

#### `ConversionPipeline`
Represents the constructed pipeline instance ready for execution. This member is typically the result of building the chain of stages.

#### `ConversionPipeline AddStage<TInput, TOutput>(...)`
Registers a new stage into the pipeline sequence.
*   **Parameters**:
    *   `TInput`: The expected input type for the stage.
    *   `TOutput`: The type produced by the stage.
    *   (Implicit) The stage instance or factory to be added.
*   **Return Value**: The updated `ConversionPipeline` instance to allow fluent chaining.
*   **Remarks**: Ensures type compatibility between the output of the previous stage and the input of the new stage.

#### `PipelineBuilder`
The entry point for constructing a new pipeline. It provides a fluent interface for defining the execution order.

#### `PipelineBuilder WithDownload()`
Configures the pipeline to include the initial download stage.
*   **Return Value**: The `PipelineBuilder` instance for further chaining.
*   **Effect**: Adds a `DownloadStage` as the first executable unit.

#### `PipelineBuilder WithValidation()`
Configures the pipeline to include a validation stage, typically checking file integrity or format compatibility after download.
*   **Return Value**: The `PipelineBuilder` instance for further chaining.

#### `PipelineBuilder WithConversion()`
Configures the pipeline to include the media conversion stage.
*   **Return Value**: The `PipelineBuilder` instance for further chaining.
*   **Effect**: Adds a `ConversionStage` to process downloaded artifacts.

#### `PipelineBuilder WithCleanup()`
Configures the pipeline to include a cleanup stage, responsible for deleting temporary intermediate files after successful conversion.
*   **Return Value**: The `PipelineBuilder` instance for further chaining.

## Usage

### Example 1: Building and Executing a Full Pipeline
This example demonstrates constructing a complete pipeline that downloads a video, converts it, and cleans up temporary files, then executes it asynchronously.

```csharp
using CoubDownloader.Pipeline;

public async Task ProcessCoubAsync(string url, string outputPath)
{
    // Initialize the builder and define the stage sequence
    var pipeline = new PipelineBuilder()
        .WithDownload()
        .WithValidation()
        .WithConversion()
        .WithCleanup();

    // Build the concrete pipeline instance
    var executionPipeline = pipeline.Build();

    // Execute the pipeline
    var result = await executionPipeline.ExecuteAsync(url, outputPath);

    if (result.Success)
    {
        Console.WriteLine($"Processing complete. File saved at: {result.OutputPath}");
    }
    else
    {
        Console.Error.WriteLine($"Pipeline failed: {result.Error}");
    }
}
```

### Example 2: Adding a Custom Stage to the Pipeline
This example shows how to inject a custom stage into the pipeline using the generic `AddStage` method, allowing for specialized processing between standard stages.

```csharp
using CoubDownloader.Pipeline;
using CoubDownloader.Stages;

public class MetadataExtractionStage : IPipelineStage 
{
    // Implementation details...
    public async Task<object> ExecuteAsync() { /* ... */ }
    public string TaskId { get; set; }
    public bool Success { get; set; }
    public string? OutputPath { get; set; }
    public string? Error { get; set; }
}

public async Task RunCustomPipelineAsync()
{
    var builder = new PipelineBuilder()
        .WithDownload();

    // Inject a custom stage between download and conversion
    builder.AddStage<DownloadTask, ConversionInput>(new MetadataExtractionStage());

    builder.WithConversion();

    var pipeline = builder.Build();
    await pipeline.ExecuteAsync();
}
```

## Notes

*   **Execution Order**: Stages are executed strictly in the order they are added via `PipelineBuilder` or `AddStage`. The output of stage `N` becomes the input for stage `N+1`. If a stage sets `Success` to `false`, the default pipeline behavior is to abort subsequent stages and propagate the error.
*   **Thread Safety**: The `IPipelineStage` implementations are not guaranteed to be thread-safe. A single instance of a stage should not be executed concurrently by multiple threads. However, the `PipelineBuilder` is designed to be used during the configuration phase; once `Build()` is called, the resulting `ConversionPipeline` should be treated as immutable for that specific execution context.
*   **Resource Management**: Stages involving file I/O (specifically `DownloadStage` and `ConversionStage`) hold handles to temporary files. If an exception occurs during `ExecuteAsync`, partial temporary files may remain on the disk unless `WithCleanup()` was successfully configured and reached. It is recommended to wrap pipeline execution in `try-catch` blocks to handle cleanup manually in catastrophic failure scenarios.
*   **Nullability**: Consumers must check the `Success` property before accessing `OutputPath`. Accessing `OutputPath` when `Success` is `false` will return `null`, as no valid artifact was produced. Similarly, `Error` is only populated when `Success` is `false`.
